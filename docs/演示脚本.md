# 涟漪 RippleTrace — 演示脚本

> 目标时长：**7 分钟**（含 1 分钟缓冲）
> 演示环境：Windows + `build\RippleTrace.exe` 已构建
> 全部命令均可离线运行，**不依赖网络、不依赖大模型 API**

---

## 演示前检查清单

```bat
cd RippleTrace
build.bat                      :: 必须看到 [OK] built ...\RippleTrace.exe
build\RippleTrace.exe --help        :: 确认 CLI 可用
```

- [ ] `build\RippleTrace.exe` 存在
- [ ] 终端窗口**足够宽**（≥ 110 列），否则表格会折行
- [ ] 终端**支持颜色**（Windows Terminal / VS Code 终端均可）
- [ ] 已准备一页 PPT 放架构图（见 `技术选型与架构.md` §2）
- [ ] 若现场终端不支持颜色，所有命令加 `--no-color`

**兜底**：所有输出已保存在 `demo_output.txt`，投屏失败时可直接展示。

## 第 0 幕 · 30 秒 · 提出问题

> "先问一个问题：**你改了一个底层函数，怎么知道哪些地方会被影响？**
>
> 现在的做法一般是三种：靠经验猜、全文搜索函数名、或者问大模型。
> 猜会漏；搜索会有大量误报，因为它分不清同名函数；问大模型——它看不见你的项目结构。
>
> 我们做了 涟漪 RippleTrace：**输入改了哪几行，输出谁会被影响、为什么、该重跑哪些测试。**"

---

## 第 1 幕 · 60 秒 · 扫描仓库，暴露"最危险的函数"

**命令**
```bat
build\RippleTrace.exe scan samples\tinybank
```

**预期输出（关键部分）**
```
涟漪 RippleTrace scan summary
----------------------------------------------------------------
  functions defined     : 70
  resolved call edges   : 107
  unresolved call sites : 253   (external / template / ambiguous)
  test functions        : 22
  entry points          : 22
  public-header defs    : 0
  ambiguous short names : 1

Top blast-radius functions (by direct fan-in)
  function                                         fan-in   lines
  trim                                                  6       7
  log_info                                              5       1
  log_warn                                              5       1
  AuditLog::clear                                       4       1
  Config::parse                                         4      22
  Money::from_cents                                     4       1
  log_message                                           4       5
  rotr                                                  4       3
  sha256_hex                                            4      11
  split                                                 4      14
```

**讲解词**
> "这是我们的演示仓库，一个分层的小型服务，27 个文件、70 个函数、22 个测试。
>
> 注意这张表：**扇入最高的不是那些复杂的大函数，而是 `trim`、`log_info` 这种只有几行的工具函数。**
> 这符合直觉——越底层、越小、越被到处引用，改动风险越高。
>
> 我们还主动列出了 **253 个未解析的调用点**。这些是 `std::` 外部库、模板和歧义重载。
> 我们没有假装图是完整的——**分析结果是一个下界**，这个数字必须让使用者看到。"

**（可选，若时间充裕）** 补一句歧义披露：
> "还有 1 个短名对应多个定义，我们的策略是**宁可漏、不可错**：不确定的边直接丢掉并披露，而不是随便连一条。"

## 第 2 幕 · 100 秒 · 核心：改一个底层函数，看影响面

**命令**
```bat
build\RippleTrace.exe impact samples\tinybank --fn sha256_hex --max-rows 8
```

**预期输出（关键部分）**
```
涟漪 RippleTrace change-impact report
========================================================================
Changed (1): sha256_hex

Blast radius
  impacted functions : 13   (max depth reached 4)
  by risk            : 0 critical, 0 high, 6 medium, 7 low
  tests to re-run    : 10
  change interactions: 0

Ranked impact (risk = fan-in x distance x exposure)
  risk     score depth fan-in function
------------------------------------------------------------------------
  MEDIUM   44    1     1      test_sha256_abc  [test]
          [########............]  tests/test_tinybank.cpp:32
          - direct caller of a changed function
          - entry point
          - covered by at least one test path
  MEDIUM   36    2     3      AuditLog::record
          [#######.............]  src/audit.cpp:17
          - shared by 3 callers
          - 2 hops from a change
          - small utility with wide reuse
          - covered by at least one test path
  ...

Why (shortest call path change -> impact)
  [MEDIUM] test_sha256_abc -> sha256_hex
  [MEDIUM] AuditLog::record -> audit_fingerprint -> sha256_hex
  [LOW]    test_account_transfer_rules -> AccountService::transfer
           -> AuditLog::record -> audit_fingerprint -> sha256_hex
  ...

Recommended test selection
  T test_sha256_abc  (tests/test_tinybank.cpp, 1 hop)
  ...
```

**讲解词（这一幕是全场重点，分三层讲）**

**第一层——数字**
> "改 `sha256_hex`，影响 **13 个函数，最深跨 4 层**：从加密原语，到审计模块，
> 到账户转账，最后到集成测试。需要重跑 **10 个测试**。"

**第二层——证据链**
> "但真正重要的不是这个数字，而是**每一条都带证据**。
>
> 看这条：
> `test_account_transfer_rules -> AccountService::transfer -> AuditLog::record -> audit_fingerprint -> sha256_hex`
>
> 一条完整的调用链，每一跳都是调用图里真实解析出来的边，带文件和行号。
> **这不是模型猜的，这是从图里走出来的。**
>
> 这正是大模型做不到的地方——它可以告诉你'注意测试可能受影响'，
> 但它算不出具体是哪 4 层、哪条路径。"

**第三层——风险成因可解释**
> "风险分不是黑盒。每个函数下面列出**为什么给它这个分**：
> '直接调用者'、'扇入 3'、'小函数高复用'、'有测试覆盖'。
> 有测试覆盖会**降低**风险，没有测试路径可达会**加分**——因为那是真正危险的地方。"

**（若被问到"这跟全文搜索有什么区别"）** 现场演示：
```bat
build\RippleTrace.exe impact samples\tinybank --fn clear --no-color
```
> "搜索 `clear` 会命中一堆同名函数。我们做的是**作用域感知的解析**：
> 唯一匹配才连边，歧义就披露。"

## 第 3 幕 · 90 秒 · 从补丁自动推导：不需要手工指定

**命令**
```bat
build\RippleTrace.exe diff samples\tinybank --diff samples\tinybank\changes.patch --max-rows 6
```

**预期输出（关键部分）**
```
Patch touches 1 file(s), +10 -2 line(s); 1 function body(ies) modified.
  * trim  src/strings.cpp:9-15  (2 added lines)
  [attributed added ranges, current-tree line numbers: 9-9, 14-14]

涟漪 RippleTrace change-impact report
========================================================================
Changed (1): trim

Blast radius
  impacted functions : 16   (max depth reached 3)
  by risk            : 0 critical, 1 high, 12 medium, 3 low
  tests to re-run    : 10
  change interactions: 0

Ranked impact (risk = fan-in x distance x exposure)
  risk     score depth fan-in function
------------------------------------------------------------------------
  HIGH     50    1     4      Config::parse
          [##########..........]  src/config.cpp:11
          - moderate fan-in (4 direct callers)
          - direct caller of a changed function
          - covered by at least one test path
  ...
```

**讲解词**
> "实际开发中你不会手工报函数名，你只有一个 `git diff`。
> 我们把补丁解析成**改了哪些函数**，然后自动跑影响面分析。
>
> 这个补丁改的是 `trim()`——一个只有 7 行的字符串工具函数。
> 影响 **16 个函数**，包括 `Config::parse`（HIGH）、`Money::parse`、`UserService::add_from_record`，
> 最后传导到 AI 顾问模块。
>
> **这就是我们要讲的核心痛点：一个 7 行的性能优化，安静地影响了大半个系统。**"

**这里有一个技术亮点，值得主动讲**
> "补丁归属这一步有个坑，我们踩过并且修好了。
>
> 补丁 hunk 里的行号是**补丁之后**的坐标，但我们分析的是**当前工作树**，也就是补丁之前的版本。
> 如果直接拿补丁行号去比函数范围，插在函数上方的代码会把后面所有行号整体下移，归属就错了。
>
> 我们的解法是解析时维护新旧行号偏移 `oldPos = newLine - netAdded + netRemoved`，
> **用旧侧行号做归属**。同时相邻函数之间的空隙按中点切分，保证一行只归一个函数。
>
> 效果：这个补丁早期版本会误报 2–3 个变更函数，现在是**精确 1 个**。"

## 第 4 幕 · 45 秒 · 变更交互冲突

**命令**
```bat
build\RippleTrace.exe impact samples\tinybank --fn trim --fn to_lower --no-color --max-rows 2
```

**预期输出（关键部分）**
```
Blast radius
  impacted functions : 20   (max depth reached 3)
  ...
  change interactions: 1

Change interactions (cannot be validated separately)
  ! to_lower  <->  trim
      shared caller depends on both changes; e.g. test_strings_basics
```

**讲解词**
> "当一个提交同时改了多个函数，有个隐藏问题：**它们能不能独立验证？**
>
> 我们检测两种情况：一个变更函数调用另一个（直接依赖），
> 或者两者被同一个调用者共同依赖。
>
> 这里 `trim` 和 `to_lower` 被 `test_strings_basics` 同时调用——
> 意味着你没法只验证其中一个，必须一起验证。这个信息直接决定了 code review 的策略。"

## 第 5 幕 · 40 秒 · 落地形态：CI 与可视化

**命令**
```bat
build\RippleTrace.exe impact samples\tinybank --fn sha256_hex --quiet ^
   --json samples\out\impact.json ^
   --dot  samples\out\impact.dot ^
   --test-list samples\out\tests.txt
```

**讲解词 + 展示**
> "三种输出形态，对应三种使用场景：
>
> **`--json`** —— 给 CI 用。可以在流水线上设门禁：影响面里出现 CRITICAL 就要求双人 review。
>
> **`--test-list`** —— 直接喂给测试运行器。**只跑受影响的测试，不用跑全量。**
> 对大仓库来说这是实打实的时间节省。
>
> **`--dot`** —— Graphviz 影响图，可以嵌进 PR 评论里，一眼看出改动波及范围。"

**展示 `impact.dot` 渲染图**（PPT 放一张 SVG 截图）
> "红色是变更点，蓝色是测试，箭头方向是调用方向。
> 一眼就能看出这个改动是怎么从底层往上蔓延的。"

## 第 6 幕 · 30 秒 · 收尾与展望

> "总结一下我们做的是什么：
>
> 市面上已经有很多'AI 读你的代码给建议'的工具，**我们不重复做那件事**。
> 那些是大模型擅长的语义工作，而且已经有巨头在做。
>
> 我们做的是大模型**结构上做不到**的事：**精确的项目级影响面推理，每条结论可验证。**
>
> 下一步是 v0.5，也是我们最想做的方向：
> **让静态分析给大模型提供它自己算不出来的结构事实，再由大模型解释每个受影响点该怎么改。**
> 结构归静态分析，语义归大模型——这才是这个方向正确的分工。"

## Web 演示（有投影、时间充裕时，约 2 分钟）

`serve.bat` 会启动本地服务并自动打开浏览器，页面**自动载入演示仓库并分析 `sha256_hex`**，
不需要任何输入就能看到完整结果。

**讲解词（看着页面讲）**

> "这是同一套分析引擎的网页界面。左边红色的节点是变更点，向右按调用深度逐层展开调用者。
>
> 注意这个形状：**深度 1 有 4 个直接调用者，深度 3 又扩散到 4 个**——
> 一个加密原语的小改动，经过审计模块传导到了账户转账，最后到达集成测试。
>
> **点一下任意节点**，它会高亮这个函数到变更点的完整调用链，并在下方给出证据行。
> 这就是我们和'大模型读代码'最本质的区别——**每一条结论都能点开看到它是怎么推出来的**。
>
> 下面四个标签页分别是：受影响函数（带风险成因）、建议重跑的测试、
> 变更交互、以及**局限说明**——最后这一页我们主动写明有 253 个调用点没能解析。
>
> 界面右上角显示的服务是**原生 winsock 实现的，没有引入任何第三方库**，
> 前端就是一个自包含的 HTML 文件。"

**如果评委问"界面能改成我们的 CI 用吗"**

> "可以，`serve` 同时暴露了 JSON 接口：`/api/scan`、`/api/impact`、`/api/diff`。
> 我们自己的命令行 `--json` 和这个走的是同一套分析结果。
> 另外服务有沙箱限制——启动时指定根目录，分析请求不能越出这个目录，越权返回 403。"

**风险提示**：浏览器演示依赖现场网络配置（localhost 一般没问题），
但如果投影环境有问题，**立刻切回命令行演示**，不要在现场调浏览器。

## 现场风险与应对

| 风险 | 应对 |
|---|---|
| 终端不支持颜色，输出乱码 | 所有命令加 `--no-color`；或直接演示 `demo_output.txt` |
| 终端太窄，表格折行 | 提前调宽；或把输出重定向到文件后用编辑器展示 |

| 时间被压缩到 3 分钟 | 砍掉第 1、4、5 幕，只讲**第 2 幕 + 第 3 幕**（核心价值全在这两幕） |
